# Part 1 — 按下 Rect 按鈕後發生什麼事

## 相關程式碼（UMLEditor）

按鈕在 `addModeButton` 裡建立，每顆按鈕都掛一個 listener：

```java
private void addModeButton(JPanel panel, String name, Mode mode) {
    JButton btn = createBaseButton(name);
    modeButtons.put(mode, btn);                         // 記「模式 → 按鈕」對照表
    btn.addActionListener(e -> canvas.setCurrentMode(mode));   // ★ 按鈕被按時，只叫 Canvas 換模式
    panel.add(btn);
}
```

> 注意：傳進來的 `mode` 會被 Lambda「捕獲」。Rect 按鈕的 `mode` 就是 `new CreateObjectMode(canvas, new RectFactory())`。

按鈕「變色」的邏輯**不在這裡**，而在另一個方法：

```java
private void highlightActiveButton(Mode activeMode) {
    for (JButton b : modeButtons.values()) {   // 全部先變白（未選取）
        b.setBackground(BTN_INACTIVE_BG);
        b.setForeground(BTN_INACTIVE_FG);
    }
    JButton active = modeButtons.get(activeMode);   // 找出目前模式對應的按鈕
    if (active != null) {                           // 把它變黑（選取中）
        active.setBackground(BTN_ACTIVE_BG);
        active.setForeground(BTN_ACTIVE_FG);
    }
}
```

而 `highlightActiveButton` 是在啟動時被「註冊」成 Canvas 的模式變更監聽器：

```java
canvas.setModeChangeListener(this::highlightActiveButton);
```

## 完整呼叫鏈（時間順序）

```
你用滑鼠點「Rect」按鈕
 1. Swing 偵測到按鈕被啟用 → 產生 ActionEvent
 2. 觸發按鈕註冊的 ActionListener → 執行 Lambda： e -> canvas.setCurrentMode(rectMode)
 3. Canvas.setCurrentMode(rectMode):
       currentMode = rectMode                          // ① 換「大腦」
       modeListener.onModeChanged(rectMode)            // ② 廣播「模式變更」事件
          → UMLEditor.highlightActiveButton(rectMode)  //    （這就是步驟 setModeChangeListener 掛上去的回呼）
                → 所有按鈕變白
                → modeButtons.get(rectMode) = Rect 按鈕 → 變黑
 4. 結束：currentMode = rectMode，Rect 按鈕高亮
```

接著你在畫布上操作：

```
你在畫布按下滑鼠
 → Canvas 的 MouseAdapter.mousePressed(e)
       → currentMode.mousePressed(e)      // currentMode 現在是 rectMode
             → CreateObjectMode.mousePressed：開始記錄起點、準備畫矩形
```

## 為什麼「變色」要繞一圈，不直接寫在按鈕 listener 裡？

因為「需要把按鈕變色」有**兩條路徑**：
1. 使用者**點工具按鈕** → 換模式。
2. 畫完物件/連線 → Canvas **自動回到 Select 模式**（`returnToDefaultMode`）。

兩條路徑最後都會呼叫 `Canvas.setCurrentMode` → 發出 `onModeChanged` 事件。只要把「變色」寫在事件的回呼 `highlightActiveButton` 裡，**兩條路徑就共用同一段變色邏輯**，不必各寫一次。這就是把按鈕 listener 寫得極簡（只 `setCurrentMode`）的原因。

# Part 2 — ActionListener / MouseListener / MouseAdapter 的差別

## 一張圖看懂三者層級

```
語意層（高階）：  ActionListener   →「這個元件被啟用了」（按鈕被按、選單被選、文字框按 Enter）
                                     不在乎你是用滑鼠點還是鍵盤 Enter

原始層（低階）：  MouseListener    →「滑鼠在 (x,y) 按下/放開/進入/離開」
                 MouseMotionListener →「滑鼠拖曳/移動」
                                     知道座標、哪個鍵、點幾下

工具類別：        MouseAdapter     → 把上面 Mouse 系列介面「全部空實作」，
                                     讓你只覆寫需要的那幾個方法
```

## 逐一說明

### ① ActionListener（介面，語意層）

- **是什麼**：一個**函式介面**，只有一個方法 `actionPerformed(ActionEvent e)`。
- **何時觸發**：元件被「啟用」時。按鈕被點、選單項被選、文字框按 Enter 都算——**它不管你是怎麼啟用的**（滑鼠或鍵盤都會觸發）。
- **用在哪**：`JButton`、`JMenuItem`、`JTextField` 這類「有『被啟動』概念」的元件。
- **怎麼註冊**：`button.addActionListener(...)`。
- **因為只有 1 個方法** → 是函式介面 → 可以用 **Lambda**：
  ```java
  btn.addActionListener(e -> canvas.setCurrentMode(mode));
  ```
- **ActionEvent e** 帶的是「哪個指令、來源是誰」（`getActionCommand()`、`getSource()`），**沒有座標**——因為按鈕不需要知道你點在按鈕的哪個像素。

### ② MouseListener（介面，原始層）

- **是什麼**：一個介面，有 **5 個方法**：
  `mouseClicked`、`mousePressed`、`mouseReleased`、`mouseEntered`、`mouseExited`。
- **何時觸發**：原始滑鼠動作（在某元件上按下、放開、點擊、游標進入、游標離開）。
- **MouseEvent e** 帶的是 `getX()`、`getY()`、哪個鍵、點擊次數——**有座標**。
- **麻煩點**：因為有 5 個方法，它**不是函式介面**，不能用 Lambda。直接 `implements MouseListener` 就**5 個方法全都要寫**（即使只需要其中 1 個，其他也得留空）。

> 另有 `MouseMotionListener`（2 個方法：`mouseDragged`、`mouseMoved`）和 `MouseWheelListener`（滾輪）。

### ③ MouseAdapter（抽象類別，工具）

- **是什麼**：一個**抽象類別**，它已經把 `MouseListener` + `MouseMotionListener` + `MouseWheelListener` 的**所有方法都空實作**好了。
- **解決什麼**：你繼承它，就**只需覆寫需要的那幾個方法**，不用把一堆用不到的空方法全列出來。
- 本專案的用法：
  ```java
  MouseAdapter ma = new MouseAdapter() {
      @Override public void mousePressed(MouseEvent e)  { currentMode.mousePressed(e); }
      @Override public void mouseDragged(MouseEvent e)  { currentMode.mouseDragged(e); }
      @Override public void mouseReleased(MouseEvent e) { currentMode.mouseReleased(e); }
      @Override public void mouseMoved(MouseEvent e)    { currentMode.mouseMoved(e); }
  };
  ```
  只覆寫這 4 個，其餘（mouseClicked、mouseEntered、mouseExited、mouseWheelMoved…）保持空實作。

### ④ addXxxListener（方法，負責「註冊」）

這些是「把監聽器掛到元件上」的動作：

- `addActionListener(l)`：掛 ActionListener。
- `addMouseListener(l)`：掛 MouseListener（負責 press/release/click/enter/exit）。
- `addMouseMotionListener(l)`：掛 MouseMotionListener（負責 drag/move）。

**本專案 Canvas 為什麼要掛兩個？**
```java
addMouseListener(ma);        // 讓 mousePressed / mouseReleased 會被觸發
addMouseMotionListener(ma);  // 讓 mouseDragged / mouseMoved 會被觸發
```
因為 `mousePressed/Released` 屬於 `MouseListener`，`mouseDragged/Moved` 屬於 `MouseMotionListener`，是**兩個不同介面**。同一個 `ma` 物件（MouseAdapter 同時實作了兩者）必須**分別註冊到兩條管道**，這 4 個方法才會全部生效。

## ⚠️ 兩個容易講錯的觀念（正確 vs 易錯）

整理註解時很容易把下面兩點講反，特別留意：

### 易錯 1：「Adapter / Listener 是『設定』一個監聽器」

| ❌ 易錯說法 | ✅ 正確說法 |
|---|---|
| 「Adapter、Listener 就是設定一個監聽器」 | **Listener / Adapter 本身「就是」監聽器**（監聽事件的那個物件），不是「設定」這個動作 |

精確區分：
- **Listener**（如 `MouseListener`）＝ 介面／契約，規定「要有哪些方法」。
- **Adapter**（如 `MouseAdapter`）＝ 抽象類別，把該介面方法**全部空實作**，方便只覆寫需要的。
- 兩者做出來的物件，最後都是「一個監聽器」。

### 易錯 2：「`addXxxListener()` 偵測行為然後傳給 Listener」

| ❌ 易錯說法 | ✅ 正確說法 |
|---|---|
| 「addXxxListener() 偵測行為，然後傳給 Listener 做動作」 | **addXxxListener() 只負責『註冊』**；偵測行為的是元件 / Swing 系統，偵測到才回頭呼叫監聽器 |

正確順序：
```
addXxxListener(監聽器)          → 只是「把監聽器登記到元件上」（一次性）
（之後）元件 / Swing 偵測到動作   → 才去呼叫你註冊的那個監聽器的對應方法
```
也就是：**「偵測」是系統在註冊之後做的事，`addXxxListener` 本身不偵測，只登記。**

## 對照表

| 項目 | ActionListener | MouseListener / MouseAdapter |
|---|---|---|
| 種類 | 介面（1 方法） | MouseListener 是介面（5 方法）；MouseAdapter 是抽象類別 |
| 抽象層級 | 語意層（「被啟用」） | 原始層（「滑鼠在哪按下」） |
| 事件物件 | `ActionEvent`（指令、來源；**無座標**） | `MouseEvent`（**有座標**、哪個鍵、點幾下） |
| 觸發來源 | 滑鼠點 **或** 鍵盤 Enter 都算 | 只有實體滑鼠動作 |
| 能否用 Lambda | ✅ 可（1 方法＝函式介面） | ❌ MouseListener 5 方法不行 → 改用 MouseAdapter |
| 典型用在 | 按鈕、選單、文字框 | 畫布、需要座標/拖曳的元件 |
| 本專案 | 工具按鈕、選單項 | Canvas（畫圖、拖曳、選取） |

## 為什麼按鈕用 ActionListener、畫布用 MouseAdapter？

- **按鈕**：只在乎「**被按了沒**」，不需要座標，也希望鍵盤操作（Enter）一樣有效 → 用語意層的 `ActionListener`，還能用一行 Lambda，最簡潔。
- **畫布**：要根據**滑鼠座標**畫圖、要區分**按下／拖曳／放開／移動**來做不同事 → 必須用原始層的滑鼠事件；又因為 MouseListener 方法太多，所以用 `MouseAdapter` 只覆寫需要的。

# Part 3 — 名詞速查

| 名詞 | 一句話 |
|---|---|
| Listener（監聽器） | 「事件發生時要被呼叫的物件」，你寫好它、註冊上去，事件來就跑它 |
| Adapter（轉接器/方便類別） | 把某介面的所有方法先空實作好，讓你只覆寫需要的 |
| `addXxxListener` | 把監聽器「註冊」到元件上的動作（沒註冊＝事件來了也不會通知你） |
| ActionEvent | 語意事件包裹（指令、來源） |
| MouseEvent | 滑鼠事件包裹（座標 x/y、哪個鍵、點幾下） |
| EDT | Event Dispatch Thread，Swing 專門處理 UI 事件與繪圖的執行緒 |

# 口試速答

- **按下 Rect 按鈕怎麼運作？**
  > 按鈕的 ActionListener 只呼叫 `canvas.setCurrentMode(rectMode)`。setCurrentMode 一邊換 `currentMode`，一邊發出 `onModeChanged` 事件，回呼到 `highlightActiveButton` 去把 Rect 按鈕變黑。所以「換模式」和「按鈕變色」都由這條事件鏈完成，按鈕自己只負責觸發。

- **ActionListener 與 MouseListener 差在哪？**
  > ActionListener 是語意層（元件被啟用，滑鼠或鍵盤都算，無座標，1 個方法可用 Lambda）；MouseListener 是原始層（滑鼠按下/放開/移動，有座標，5 個方法）。按鈕用前者、畫布用後者。

- **MouseAdapter 是什麼、為什麼用它？**
  > 它是抽象類別，把 Mouse 系列介面全部空實作。因為 MouseListener 有 5 個方法、不能用 Lambda，用 MouseAdapter 就能只覆寫需要的幾個方法，不必寫一堆空方法。

- **為什麼 Canvas 要 addMouseListener 又 addMouseMotionListener？**
  > 因為 press/release 屬於 MouseListener、drag/move 屬於 MouseMotionListener，是兩個介面。同一個 MouseAdapter 物件要分別註冊到這兩條管道，四種事件才會都生效。
